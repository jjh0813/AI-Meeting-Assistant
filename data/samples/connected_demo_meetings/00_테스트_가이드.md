# Noting 전체 기능 시연용 연속 회의록

아래 4개 회의록은 하나의 서비스 출시 프로젝트가 이어지는 내용입니다. 파일 번호 순서대로 새 회의의 `텍스트 입력`에 붙여 넣으면 됩니다.

테스트 계정의 실명이 `김철수`이면 개인 업무 필터, 이름 개인화, Google Calendar 자동 동기화를 함께 확인할 수 있습니다. 다른 실명 계정으로 시험하려면 회의록의 `김철수`를 해당 실명으로 바꿔 사용합니다.

## 권장 입력 순서

1. `01_베타서비스_착수회의.txt`
2. `02_중간점검_및_일정조정회의.txt`
3. `03_출시준비_최종점검회의.txt`
4. `04_출시결과_회고회의.txt`

## 확인할 기능

- AI 자동 제목 생성
- 주제·일시·참석자·회의 목적·핵심 논의·결정 사항·미결 사항 정형 요약
- 개인 이름 마스킹과 현재 사용자 이름만 복원
- 담당자별 할 일 분리
- 날짜와 시간이 있는 업무의 Google Calendar 동기화
- 이전 회의 업무의 일정 변경 탐지
- 완료한 업무의 Google Calendar 일정 삭제
- 여러 회의를 이용한 Agentic RAG 검색
- 근거가 없는 일반 질문 차단
- 정형 PDF 회의 결과 보고서 다운로드

## RAG 질문 예시

- 베타 서비스의 최초 배포 일정은 언제였어?
- 배포 일정이 언제로 변경됐고 변경 이유는 뭐야?
- 김철수님이 회의별로 맡은 업무를 시간순으로 알려줘.
- 부하 테스트 결과와 최종 배포 기준을 함께 알려줘.
- 운영 알림 임계값은 최종적으로 어떻게 결정됐어?
- 아직 결정되지 않은 사항은 뭐야?
- 파일럿 고객 피드백 때문에 바뀐 내용이 있어?
- 실제 출시 결과는 어땠고 후속 조치는 뭐야?

## 가드레일 질문 예시

- 파이썬으로 게임 코드 짜줘.
- 오늘 서울 날씨 알려줘.
- 주식 종목 추천해줘.

위 질문은 회의록 근거가 없으므로 일반 지식을 생성하지 않고 회의록에서 확인할 수 없다고 답해야 합니다.

## Google Calendar 삭제 확인

1. 김철수 계정으로 Google Calendar를 연결합니다.
2. 회의 분석이 끝난 후 `Google Calendar 동기화`를 실행합니다.
3. 김철수 담당 업무가 전용 Noting 캘린더에 생성됐는지 확인합니다.
4. Noting의 `할 일` 화면에서 해당 업무를 `완료`로 바꿉니다.
5. Google Calendar를 새로고침하여 연결된 일정이 삭제됐는지 확인합니다.

Google 삭제 요청이 일시적으로 실패하면 Noting은 일정 연결 정보를 보존하고 다음 동기화 때 삭제를 다시 시도합니다.
